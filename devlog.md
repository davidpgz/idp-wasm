### 2025-03-30. Update K8s resources and IaC

To manage infrastructure I'm more used to Infrastructure as Code (IaC) and more specifically how Pulumi does it then using command line with Helm to manage the infrastructure state. I have been using helm commands until now because they are present in the tutorial I've followed so far. My hidden goal was to replace all of that with something that allows me to add and udpate resources with a single command. Since I started to update existing resource I felt that it was about time to look for a simpler and less error-prone way to deploy changes to my k8s cluster. Helmfile define it self as a declarative way to deploy Helm Charts. Even though it is true that I was using yaml files (helmfile) within my helm commands there is a bunch of command arguments that are not captured by the helmfile. Furthemore, I have to know if the resource is already present in the cluster to decide between `helm install` to create a new resource or `helm upgrade` to update it. Here comes Kustomize which allow to "fully" (I think) represent resources as yaml files and to apply the changes to multiple resources within the same folder with the command `kubectl apply -k <kustomization_directory>`. It seems promising, but more reading lead me to think that Kustomize does not support resource removal if a kustomization file is removed after a deployment. This is how I circled back to Pulumi which to my surprise offer tooling to convert both helmfile and kustomization file into pulumi code. I'll give it a shot since it will allow me to represent everything I have much more cleanly while also managing resources changes with one single command `pulumi up`. My next step would be to convert everything to pulumi stack.

### 2025-03-30. Cluster Observability

While searching monitoring solution for k8s cluster, I've considered Prometheus and then OpenMetrics which seems to be the standardized successor. Somehow I had difficulty to find a tutorial to integrate OpenMetrics to a k8s cluster, which made me search for an alternative. I landed on OpenTelemetry which support traces and also logs and metrics. It sound to be more promising option on the long run since it supports the three pillar of observability (metrics, logs and traces) while Prometheus is mainly focused on metrics. Furthermore the tutorial for OpenTelemetry in k8s was easy to follow and integrate in my local k8s cluster, exactly what I was looking for. At the end of the tutorial, I finally understood that I was halfway there, OpenTelemetry does not include data visualization.
